# 0.16.33

- **feat(workitem/#95):** `workitem create` 创建前一次性预检必填字段，不再"POST → 报一个缺失 → 补 → 再报下一个"。
  - 在 POST 之前（`--dry-run` 也执行）发一次只读 `GET .../workitemTypes/{typeId}/fields`（与 `workitem fields` 同一端点），与**最终请求体**对照：flag、`--description-file` / `--custom-fields-file`、profile `workitem_defaults` 都已合入之后再检查。
  - 缺失时 exit 1、不发 POST：`error.subtype=missing_required_fields`，message 列出全部缺失字段（`名称 (fieldId)`），`error.details.missing[]` 含 `field_id` / `name` / `format` / `type` / `pass_via`（原生字段给出对应 flag，其余为 `customFieldValues`，经 `--custom-fields(-file)` 传入）/ `options`（最多 20 个，另给 `options_total`）；hint 指向 `--custom-fields(-file)`、`workitem fields` 与 `--no-precheck`。
  - 不检查：非必填、`showWhenCreate=false`、服务端托管字段（status / creator / workitemType 等）、带服务端 `defaultValue` 的字段（避免误报；其 id 列在 `meta.precheck.skipped_default`）。根级字段（subject / sprint / labels …）只认 flag（根级 key），其余字段只认 `customFieldValues`。空字符串 / 空白 / 空数组视为缺失；数字与布尔视为已填。
  - 字段配置 GET 401 → 直接失败。其他读不到（HTTP 错误、网络、返回形状异常；最多重试 1 次、退避 ≤1s）→ `status=skipped`；返回空列表 → `status=empty`；均照常创建，`reason` / `hint` / `warning` 写在 `meta.precheck`（不向 stderr 打印纯文本）。profile 有 `workitem_defaults[type].create_required` 时按其兜底检查（`source=profile_fallback`，`profile_missing[]`，只告警）。
  - 成功时 `meta.precheck={status:"ok",source:"fields",required_checked:n,skipped_default?}`；dry-run 在 `request.precheck` 展示。`--no-precheck` 跳过该 GET 且不写 meta。用户传入的值从不被修改；其他服务端校验错误原样透传。
  - **兼容性：** `--dry-run` 需要凭证与网络且缺必填时 exit 1；缺字段报错由服务端 `type:"api"` 400 变为 `type:"cli"` + `missing_required_fields`；每次 create 多一次 GET；`--no-precheck` 恢复旧行为（离线使用）。
  - 详见 [workitem-create-precheck](../02-domains/workitem-create-precheck.md)。
