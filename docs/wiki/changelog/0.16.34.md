# 0.16.34

- **feat(workitem/#98) — BREAKING（输出形状）:** `workitem get` 默认不再展开 description。
  - 默认（等同 `--brief`）：`data` 只含 `id` / `serialNumber` / `subject` / `status {id, displayName}` / `assignedTo` / `sprint` / `priority` / `gmtModified`，以及 `description_summary`（如 `(description: 3214 chars, use --full or --fields description)`，按字符数计）；缺失或为 null 的字段省略。`priority` 取自 `customFieldValues` 中 `fieldId="priority"` 的首个值（`{id, displayValue}`；API 若有顶层 `priority` 则原样使用）。`meta.projection="brief"`。
  - `--full`：原始 GetWorkitem 对象，`data` 与 `meta` 与 0.16.33 及以前完全一致（不加 `meta.projection`）。
  - `--fields a,b,c`：只保留这些顶层字段（原始值；存在但为 null 的保留为 null；`priority` 同上派生）。大小写敏感、去重；空项 / 嵌套路径（`status.id`，请用 `--jq`）/ 非法名在请求前报错；返回中不存在的名字在读取后报错 `error.subtype=unknown_fields`，`details` 含 `unknown` / `available` / 大小写建议 `suggestions`，stdout 不输出。`meta.projection="fields"`。
  - `--full` / `--brief` / `--fields` 互斥（`--full=false` 视为未传），冲突在请求前报错（`--dry-run` 同样）。`--dry-run` 不发请求，在 `request.projection` 展示所选视图（`--full` 不加该字段）。
  - 所有视图保留 `meta.url` / `serial_number` / `resolved_id`（由完整对象计算后再投影）与 `{ok,data,meta}` 信封；API 错误照常透传（`type:"api"`）。
  - **迁移：** `--jq` 作用于投影后的信封；读取 `.data.description` / `.data.customFieldValues` 等非 brief 字段的脚本请加 `--full`（或 `--fields`）。仓库内 skill / 文档未依赖旧的全量输出。
  - 详见 [workitem-get-views](../02-domains/workitem-get-views.md)。
