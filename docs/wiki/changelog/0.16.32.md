# 0.16.32

- **feat(codeup/#94):** `codeup mrs diffs` 标记最新 patchset：`data` 中每个 patchset 对象新增 `latest: true|false`（至多一条为 true），`meta` 新增 `latest_patchset_biz_id`（无候选时省略）与 `latest_version_no`（缺失时省略）。
  - `latest` 由 CLI 注入到 API 原始对象中；若 API 返回同名字段，会被 CLI 的值**覆盖**。其余原字段不删不改名、保持 API 返回顺序，`{ok,data,meta}` 信封不变。
  - 「最新」与 `comments create` 缺省 patchset（#93）同一规则（`internal/mrpatchset.Latest`）：候选为 MERGE_SOURCE；仅当整批**完全没有带类型的条目**时才用未带 `relatedMergeItemType` 的条目；MERGE_TARGET 永不选中。排序：versionNo 最大 → 有可解析 createTime 的优先 → createTime 最新（RFC3339；无时区按 UTC；≥10 位纯数字按 epoch 秒/毫秒）→ 返回顺序靠后。
  - 无候选时全部 `latest:false`，仍 `ok:true`：空列表 / 仅 MERGE_TARGET / 有 MERGE_TARGET 但无 MERGE_SOURCE（即使同时有未带类型的条目）。
  - 一次调用即可定位：`--jq '.meta.latest_patchset_biz_id'`，或 `--jq '.data[] | select(.latest)'`（后者假设 `data` 为数组，即通常的返回形状）。未采用 `--latest`（会改变 `data` 形状，且 jq 过滤已足够）。
