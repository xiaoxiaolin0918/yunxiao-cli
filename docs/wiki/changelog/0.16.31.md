# 0.16.31

- **feat(codeup/#93):** `codeup mrs comments create` 的 `--patchset-biz-id` 对 GLOBAL_COMMENT 改为可选：缺省时 CLI 先读 `GET .../diffs/patches`，取**最新 MERGE_SOURCE** patchset（versionNo 最大，其次 createTime 最新，再其次返回顺序靠后；没有任何 MERGE_SOURCE 条目时退而使用未带 `relatedMergeItemType` 的条目；MERGE_TARGET 永不选中；兼容旧字段 `patchSetNo` / `createdAt` 与 `{result:[...]}` 包裹）。`--dry-run` 在 `request.resolved` 展示 `patchset_biz_id` / `patchset_source=latest` / `version_no`（解析为只读 GET，dry-run 同样执行）；成功时 `meta.patchset_biz_id` + `meta.patchset_source=latest`。显式传入始终优先且不发起解析请求；INLINE_COMMENT 仍必填；MR 无（源）patchset 或 GET 失败时直接报错（不回退），提示中带实际的 `mrs diffs --repo <值> --local-id <n>` / 显式传参。回复（`--parent-comment-biz-id`）未显式传 patchset 时同样挂到最新 patchset，而非父评论所在版本（OpenAPI 不要求一致；需要同版本请显式传入父评论的 `related_patchset.patchSetBizId`）。解析逻辑在 `internal/mrpatchset`（`Parse` / `Latest`），供 #94 复用。
- **fix(codeup/#93 review):** `--comment-type` 大小写不敏感并校验（仅 `GLOBAL_COMMENT` / `INLINE_COMMENT`），只有 GLOBAL 自动解析 patchset——避免 `inline_comment` 走缺省路径并静默丢掉 `file_path` / `line_number`。解析失败统一包装为 `resolve latest patchset for MR <n>: …`，HTTP 错误保持 `type:"api"` + 状态码 + 原 hint，并追加"显式传 `--patchset-biz-id`"提示。`Latest` 改为全序（versionNo → 是否有可解析 createTime → createTime → 位置），结果不再依赖返回顺序；未带类型条目仅在整批无 MERGE_SOURCE/MERGE_TARGET 时作为候选；数字毫秒 `createTime` 不再变成科学计数法，`"3.0"` 视为 3，无时区时间按 UTC。dry-run `request.resolved` 新增 `resolved_via`，缺失 `version_no` 时省略。写路径复用 `runJSONMutating`（新增 `runJSONMutatingPreview` 以携带 `resolved`）。
