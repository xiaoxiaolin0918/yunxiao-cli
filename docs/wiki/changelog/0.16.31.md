# 0.16.31

- **feat(codeup/#93):** `codeup mrs comments create` 的 `--patchset-biz-id` 对 GLOBAL_COMMENT 改为可选：缺省时 CLI 先发一次只读 `GET .../diffs/patches`（`--dry-run` 同样执行，需凭证与网络），取**最新 MERGE_SOURCE** patchset。
  - 候选：`relatedMergeItemType=MERGE_SOURCE` 的条目；仅当返回里**完全没有带类型的条目**时才退而使用未带 `relatedMergeItemType` 的条目（任何类型值——MERGE_TARGET 或未知值——都关闭该回退，此时无 MERGE_SOURCE 即报错）；MERGE_TARGET 永不选中。兼容旧字段 `patchSetNo` / `createdAt` 与 `{result:[...]}` 包裹。
  - 排序为全序、与返回顺序无关：`versionNo` 最大（`"10"` > `"9"`，`"3.0"` 视为 3）→ 有可解析 `createTime` 的优先 → `createTime` 最新（RFC3339；无时区按 UTC；≥10 位纯数字按 epoch 秒/毫秒，`"20260929"` 这类短数字视为无法解析；数字毫秒不再变成科学计数法）→ 仍完全并列时取返回顺序靠后。
  - `--dry-run` 在 `request.resolved` 展示 `patchset_biz_id` / `patchset_source=latest` / `resolved_via`（`GET <diffs/patches 路径>`）/ `version_no`（缺失时省略）；成功时 `meta.patchset_biz_id` + `meta.patchset_source=latest`。显式传入始终优先且不发起解析请求。
  - `--comment-type` 大小写不敏感并校验（仅 `GLOBAL_COMMENT` / `INLINE_COMMENT`，其他值直接报错）；只有 GLOBAL 自动解析，INLINE_COMMENT 仍全部必填（避免 `inline_comment` 走缺省路径静默丢掉 `file_path` / `line_number`）。
  - 无候选或 GET 失败时直接报错（不回退、不发评论），统一包装为 `resolve latest patchset for MR <n>: …`；HTTP 错误与未包装时一致（`type:"api"` + 状态码 + 原 hint + subtype/details），hint 追加实际的 `mrs diffs --repo <值> --local-id <n>` / 显式传 `--patchset-biz-id` 提示。
  - 回复（`--parent-comment-biz-id`）未显式传 patchset 时同样挂到最新 patchset，而非父评论所在版本（官方文档未说明是否须一致；需要同版本请显式传入）。
  - 解析逻辑在 `internal/mrpatchset`（`Parse` / `Latest`），供 #94 复用；写路径复用 `runJSONMutating`（新增 `runJSONMutatingPreview` 以携带 `resolved`）。
